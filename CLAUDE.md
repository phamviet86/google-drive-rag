# CLAUDE.md

google-drive-rag is a single-process RAG service over Google Drive: a standard MCP server (Streamable HTTP at `/mcp`, plus `/healthz`) that serves any MCP client (Claude Code, OpenAI Codex, Google Antigravity, others) and a background sync loop, packaged as one Docker container. The README section "Kết nối với agent" holds the setup for each client; keep it agent-neutral. The owner is not a programmer and reads Vietnamese; `README.md` is their install guide and must stay in Vietnamese.

## Commands

Python 3.12 or 3.13, editable install in `.venv`:

```bash
python3.12 -m venv .venv && .venv/bin/pip install -e '.[dev]'
```

Run all four before calling a change done:

```bash
.venv/bin/ruff format --check .
.venv/bin/ruff check .
.venv/bin/mypy
.venv/bin/pytest
```

- One test: `.venv/bin/pytest tests/test_sync.py -k overlapping`.
- Manual search: `.venv/bin/gdrive-rag --data-dir /tmp/gdr search "query" --folder <link> --file <link>`; add `--explain` for each hit's FTS rank/score, bm25, vector rank/cosine and fused score.
- Ranking eval: `.venv/bin/python tests/test_ranking_eval.py` prints rank-of-expected per query on the synthetic corpus (FTS-only and hybrid); `test_ranking_eval` enforces the thresholds written above it. For real data, `.venv/bin/python scripts/eval_ranking.py <index copy> <query-vectors.json> [--show 3]` runs against a copy of an index with recorded live query vectors (no network); keep that data outside the repo. Re-run both after any ranking change.
- Upgrade test: `tests/test_upgrade.py` opens `tests/fixtures/v0_2_0_index.sqlite3` and `v0_3_0_index.sqlite3`, which the v0.2.0 and v0.3.0 code themselves built from synthetic files (`make_v0_2_0_index.py`, `make_v0_3_0_index.py` beside them). It asserts that no row changes and nothing is downloaded or embedded. Add a fixture like it for each schema change.
- Real OCR test: runs only when `tesseract` with `vie` and `eng` data is on PATH (CI installs it), otherwise skipped: `.venv/bin/pytest -rs -k real_tesseract`. `python -m gdrive_rag.ocr` is the same check as a command; the Docker build runs it.
- `mypy` is strict over `gdrive_rag`; ruff line length is 100.
- Run the server locally against a throwaway data dir, never a real one: `.venv/bin/gdrive-rag --data-dir /tmp/gdr serve --port 18765`, then `curl http://127.0.0.1:18765/healthz`.
- Docker: `docker compose up -d --build`; the CLI runs inside the container as `docker compose exec gdrive-rag gdrive-rag <command>`.

## Architecture

All code is in `src/gdrive_rag`. Console script `gdrive-rag` → `gdrive_rag.cli:entrypoint`.

```text
cli.py / server.py  →  service.Service  →  drive.py (DriveBackend protocol, GoogleDriveBackend)
                                        →  local.py (LocalBackend, same protocol, for `local:` sources)
                                        →  extract.py (+ formats.py, xlsx_compat.py, ocr.py)
                                        →  chunking.py → db.py (SQLite WAL, FTS5, vectors)
                                        →  embeddings.py (OpenAI-compatible client)
                       search.SearchEngine reads the same database
```

- `service.Service` is the one facade for CLI and MCP. It takes factories (`backend_factory`, `embedding_factory`, `extractor_factory`); tests inject fakes through them (`tests/helpers.py`: `FakeDrive`, `FakeEmbeddings`, `EmbeddingStub`, `make_service`; `FakeDrive.add_folder` and `put(parent=...)` build a folder tree whose paths follow folder renames and moves). `Service.reload()` re-reads settings, so a key added through the CLI takes effect on the next sync or search.
- Sync is a full listing per source compared with `DriveItem.fingerprint` (checksum or modifiedTime, size, MIME type; no name or path); there is no `changes.list`. A rename or move only updates `documents` and the FTS title (`Service._update_metadata`). `chunk_hash` is the hash of the chunk text alone, and embeddings get the text without a file-name prefix, so vectors survive renames. Documents are keyed by Drive file ID with a `document_sources` membership table, so overlapping sources share one copy.
- `GoogleDriveBackend.list_files` re-resolves the root every cycle, because `files.list` on a folder we lost access to returns an empty page instead of 404. `tests/test_drive_backend.py` drives it through a stub `service` with real `HttpError`s.
- Google Docs are exported as Markdown; `strip_data_images` removes embedded base64 images first. Drive shortcuts are skipped.
- Deletion safety: membership is replaced only from a complete listing, or cleared when the source root raises `DriveItemError` (404 / not shared). `DriveSourceError` (auth, quota, network) and incomplete listings never delete. Keep this split when touching `drive.py` or `Service._sync`.
- Download and export errors are per file: `GoogleDriveBackend.download` raises `DriveDownloadError` (stored with the `download: ` prefix and retried on every sync); only HTTP 401 and connection errors raise `DriveSourceError`, which stops the pass and skips deletions. Docs and Slides over the 10 MB export limit fall back to a `text/plain` export (`Download.suffix` becomes `.txt`).
- A sync holds an `flock` on `<data_dir>/sync.lock` and writes its PID to `sync.running`; `sync_running()` reads only the PID file. A second sync raises `SyncBusy`.
- On-demand sync: MCP `sync_now` calls `Service.request_sync`, which only records a request (at most one per `REQUEST_INTERVAL_SECONDS` = 60, refused with `retry_after_seconds`; `already_running` while a request is pending or `sync_running()`) and sets `Service.wake`. `server.SyncLoop` is the only thread that runs syncs in the server: it waits for a fixed scheduled deadline or a wake-up, runs a pending request as `sync("requested", source_id)` without moving the deadline, and retries a scheduled cycle that hits `SyncBusy` (a CLI sync) after `BUSY_RETRY_SECONDS` instead of skipping it. `sync()` records the trigger (`scheduled`, `requested`, `manual`) in `meta.last_sync_trigger`; `sync_status` shows it and `requested`. `Service.queue_sync` (used by `add_source` and `set_embedding`) is exempt from the 60-second limit and does not use up that minute. Calls coalesce into at most one queued sync. A generation counter (`begin_request` / `finish_request(gen)`) makes a sync queued while another runs run once afterwards. A pending request that finds the lock held by another process stays queued and is retried after `BUSY_RETRY_SECONDS`.
- Local sources (`local.py`): `LocalBackend` under `local_root` (`Service(local_factory=...)` for tests). IDs are `local:<relative path>` in NFC (path components are matched by NFC equality, so NFD names on disk are found), root `local:.`, kinds `local_folder` / `local_file`; the stored link is the ID, and `parse_drive_link` normalises `local:` IDs, so `read`, scopes and `list_folders` work. `add` takes `local:<rel>` or an absolute path; symlinks are resolved, and a path outside the root gets the same answer as a missing one; errors never repeat the argument. Fingerprint is size + `mtime_ns` + MIME (Python's `mimetypes` table only). Names starting with `.` and `~$` lock files are ignored, not recorded; symlinks inside the root are followed, and one that leaves the root, points to a folder, a hidden file, a protected folder or a file the same source lists, or is broken, is skipped with a reason. Skipped IDs are root-relative like item IDs. The data dir and `GDRAG_SECRETS_DIR` are protected: never listed, added or read (matched by real path and dev/ino), recorded as one skipped row each. Download opens with `O_NOFOLLOW` and checks the fd's real path is inside the root and not protected, and refuses a small plain-text file that looks like a credential (private key, service account JSON, `refresh_token`/`client_secret`, `GOCSPX-`, `ya29.`, `1//`) as a `download:` error. Errors: root missing, unreadable or empty → `DriveSourceError` (nothing deleted); a `local_folder` source that lists nothing while it holds documents → `DriveSourceError` (`Service._refuse_vanished_folder`, an unplugged disk); source path gone with the root fine → `DriveItemError` (source cleared); unreadable subfolder → incomplete listing; file read error → `DriveDownloadError`; mount vanishing mid-download → `DriveSourceError` for the local side only. Each source uses the backend of its kind and a stop applies only to its side, so Google unset or failing leaves local sources alone and the reverse. A rename is a new ID: re-extracted, but equal chunk hashes mean no re-embedding (scanned PDFs are OCR'd again). Files must be readable by uid 10001. `sync_status.local_folder` is `{configured, ok, error}`; `GDRAG_DRIVE_LINKS` may hold `local:` entries (not removable).
- Extraction failures are per file (stored as `status='error'`, retried after 24 hours or when the file changes). Missing LibreOffice raises `ExtractionError("converter_missing")`; a missing `tesseract` binary or language data sets `metadata.ocr_unavailable`. Neither may become a service error.
- OCR (`ocr.py`): `pdf-inspector` reads text PDFs and lists `pages_needing_ocr`; only those pages are rendered with `pypdfium2` at 300 dpi and sent as grayscale PNG on stdin to `tesseract stdin stdout -l <GDRAG_OCR_LANGS>` (default `vie+eng`) with a per-page timeout. Images go to Tesseract directly. Spans keep `page:N` locators with `source` `native` or `ocr`. `metadata.ocr_engine` records the engine; `service._stale_ocr` re-extracts a document with OCR pages once when that engine differs (the old PP-OCR text) or when it was `ocr_unavailable` and OCR now works. Documents without OCR pages are never re-extracted. Tests use `tests/helpers.py:FakeOCR` or a fake `tesseract` script.
- Embeddings: vectors are truncated to `embedding_dimensions` (1024) and re-normalized client-side; no `dimensions` field is sent. Only queries get the `Instruct: ...\nQuery:` prefix. `meta.embedding_identity` records endpoint, model and dims; when it changes, `embed_pending` deletes all vectors and re-embeds, and search stays FTS-only until then. A chunk the endpoint rejects (`EmbeddingError.rejected`: HTTP 400/413/422) is isolated by splitting its batch and stored in `embedding_failures`; other embedding errors stop the pass.
- Ranking (`search.py`, `ranking.py`): weighted reciprocal-rank fusion (`WEIGHTS`, k=60) of four signals. text: up to 200 FTS candidates (all terms, then any term) ordered by `lexical_score` = 0.7 x IDF-weighted share of distinct query terms present + 0.3 x share of adjacent query-term pairs (bm25 breaks ties; words no chunk contains weigh 0). vector: cosine order. title (weight 2): the same IDF-weighted coverage over file name + folder path, split on `-`, `_`, `.`, `/` and digits; equal title scores share a rank, so every chunk of the matching file gets it. phrase (weight 2): chunks containing the whole query as a phrase count as rank 1, which keeps codes and short keywords first. Tuned on a private copy of the real index with live query vectors (`scripts/eval_ranking.py`); a lexical-heavy score fusion tried before won only on the bag-of-words fake. Ranking-only: no re-index or re-embedding.
- FTS rows follow `chunks` through triggers; `fts_fold` (NFC + đ→d) plus `remove_diacritics 2` makes Vietnamese search accent-insensitive.
- Folder ancestry (migration 3): `folders` (Drive ID, name, parent ID, display path), `folder_sources` membership (same replace/keep rules as `document_sources`), `documents.parent_id`, and `document_folders` holding every ancestor folder of each document. `_refresh_ancestry` recomputes paths and `document_folders` from parent IDs at the end of each sync and on `source remove`, so a folder rename or move never re-extracts or re-embeds. When two listings report one folder, the non-empty parent wins; the stored parent is kept only when a source that held the folder failed or was incomplete, or the pass stopped. A pass stopped by `DriveSourceError` replaces neither `document_sources` nor `folder_sources`. A hit's `parent_folder_id` is null when that folder is not indexed. A file-kind source's parent folder is not in `folders`, so it is not listable.
- Search scope (`SearchEngine._scope`): `source`, `folder` (that folder and all descendants, via `document_folders`) and `files` combine as SQL conditions applied to both the FTS query and the allowed vector chunks before fusion. An unknown source, folder or file raises `ValueError` naming it. The 3-hits-per-document cap is soft: remaining slots are filled from the same files. Folder and file values go through `parse_drive_link`, so links and bare IDs both work; `read` accepts them too.
- Path rules (`rules.py`, table `path_rules`, migration 4; migration 5 adds `ignore` to its CHECK, rows kept) are per source: `demote` moves every hit of a demoted document below the best hit of the next `DEMOTE_PLACES` (10) other documents (`rules.demote`, by document, not by chunk) and lowers those scores to just below the hit above. A multiplier was tried and dropped: ×0.5 left old copies on top, and the factor that fixed one query was arbitrary for the next. `exclude` is one more scope condition (`json_each` over the excluded document IDs). At most `MAX_PATTERNS` (20) patterns per effect and source, `MAX_PATTERN_CHARS` (100) each. `server._fit_rules` / `_fit_rule_preview` trim patterns and examples so `list_sources`, `sync_status` and `set_path_rules` stay under the wire cap. Matching is a linear NFA (`rules.Glob`), never regex. Effects are memoised per (document, path, source) row, read on every query, so rules apply to files linked or moved during a sync without an `index_revision` bump. Patterns matching every path (`MATCH_ALL_PROBES`, names longer than `MAX_PATTERN_CHARS`, so `**??` is caught) are refused, and so are exclude patterns that would hide every document of a source.
  - The demoted hit's score is capped just below its anchor (best hit of the 10th next other document, or the lowest other hit), then hits are sorted by score. When demoted chunks are among the first text or vector candidates, text search runs again without them and vector candidates come from one cosine order (union ranked by each signal's own score); fusion once, then demote.
  - Only when path-rule effects exist does `_rows` put hits beyond the 3-per-file cap after every capped hit, so scores never increase and a smaller `limit` is a prefix of a larger one. Without rules `_rows` is unchanged (ranking was tuned on it).
  - `demote` and `exclude` are applied at query time only, so they never re-extract or re-embed; `ignore` is the third effect (below). With no rules the search code path is unchanged (`scripts/eval_ranking.py` output must stay byte-identical).
  - Patterns are globs over the document `path` (`*`, `?`, `**`; an unanchored pattern matches at any depth; a trailing `/` means everything below), folded with no case and no accents.
  - A document gets the rules of every source holding it; `ignore` wins over `exclude`, which wins over `demote`. A file named in `files` is never excluded.
  - `ignore` keeps items out of the index: an entry is a glob, `id:<ID>` (from a Drive link, an `id:` entry, `local:<path>` or a bare ID, taken as an ID only if the source already knows it: an indexed document or folder, or a skipped file; anything else is a glob, and the preview's `ignore_matches_nothing` / `warning` names new entries that match nothing). `rules.ignore_listing` filters each listing right after listing, before split, folder registration and download, by id, path and parent IDs; a folder is ignored if an ID names it or an ancestor, or a glob matches everything below it (`cu/` yes, `cu/*` no), so folder entries survive renames. Ignored items go to `skipped_files` as `ignored by rule: <entry>` (`SkippedFile.parent_id` optional); a file any source ignores is dropped from every listing (`ignored by a rule of another source that lists this file`). It is not membership: a complete listing removes indexed documents; an incomplete listing or `DriveSourceError` deletes nothing, but any listing that reports a file as not ignored deletes that file's ignore skipped rows. Query-time hiding uses the current entries and only skipped rows whose entry still exists. Search, `list_folders` (`SearchEngine.ignored_folders`) and `read` hide ignored items at once; `files` naming one returns nothing plus a warning. The preview counts documents and folders per entry and refuses entries that would empty a source or name the source itself. Changing `ignore` clears that source's ignore skipped rows and queues a full sync; `demote`/`exclude` queue nothing. CLI: `source rules --ignore` passes `queue=False` and says the server applies it at its next sync (or run `gdrive-rag sync`).
  - `--explain` adds `path_rule` and `fused_before_rules`, but only when some rule exists.
- First sync: `sources.first_synced_at` is set at the end of a pass that listed the source without a stop. `last_status` and `last_sync_at` are set right after listing, so they cannot mean the first sync finished.
  - `add_sources` registers a folder root in `folders` / `folder_sources`; `discard_source` drops it again.
  - `_sync` registers listed folders right after each listing. During a first sync, `_link_early` links each processed file to its sources and ancestor folders. All of this is additive, and the end of the pass replaces membership as before.
  - A scoped search on such a source warns `source 'X' is still on its first sync (N of M files indexed)`. A folder not in `folders` gives that warning (`search.NotIndexedYet`, 'unknown; it may not be indexed yet') only while a folder source still has `last_status='pending'` (not listed yet); otherwise it is a `ValueError`.
- Progress: `service.Progress` writes `meta.sync_progress` (throttled by `PROGRESS_INTERVAL_SECONDS`) and removes it when the sync ends. `status()` shows it as `sync.progress` only while `sync_running()` is true.
- Skipped files: `drive.split_supported` / `skip_reason` split listed items. `Listing.skipped` is stored in `skipped_files`, replaced from a complete listing and added to from an incomplete one. `Service._sync` applies the same split to any backend's items.
- MCP tools (`server.py`): nine always registered, plus seven admin tools behind `GDRAG_ADMIN_TOOLS`. The six read-side tools are read-only `search`, `read`, `list_sources`, `list_folders`, `sync_status`, plus `sync_now` (not read-only, not destructive, idempotent), which only asks for an early sync. `list_folders` pages folders then documents as one sequence (`offset` / `next_offset`, 100 per page, then the wire cap). Each returns `Annotated[CallToolResult, <Model>]` with the same JSON as text and structured content, trimmed until `wire_size` (both copies, after JSON escaping) is at most `MAX_WIRE_CHARS` (56,000), so a response stays under about 60,000 characters. `sync_status` takes `include_skipped`, which lists the first 100 skipped files. The three source tools (`add_source`, `remove_source`, `set_path_rules`) come from `register_source_tools`; `set_path_rules` is destructive (`ignore` removes indexed documents).
- Admin MCP tools (`admin.Admin`) exist only when `GDRAG_ADMIN_TOOLS` is 1/true/yes/on in the environment; otherwise they are not listed. That switch and `GDRAG_SECRETS_DIR` (`/secrets` in Docker) are read from the environment only, never from `config.json`, so no tool can turn the switch on or widen the secrets folder.
  - Always on (`server.register_source_tools`, no switch): `add_source`, `remove_source`, `set_path_rules`. They go through `Admin` and keep the preview/`confirm` rules below. Behind the switch (`server.register_admin_tools`), seven: `google_auth_status`, `set_google_service_account`, `google_auth_start`, `google_auth_finish`, `remove_google_auth`, `set_embedding`, `remove_embedding`. `set_embedding` takes optional `base_url` and `model` (current value kept), like Admin and the CLI.
  - Destructive tools, and `set_path_rules`, take `confirm`; without it they only preview.
  - File arguments are names inside the secrets folder, resolved with symlinks and refused outside it.
  - Every admin tool argument is typed `Any` with a default and checked in the handler, because the SDK's validation error prints the whole argument dict. The JSON type is still advertised through `server.loose`. `confirm` must be the JSON boolean `true`. Errors never repeat an argument value.
  - `set_embedding` rules:
    - A new origin (scheme, host, port) needs a new key, and the change is refused while `GDRAG_EMBEDDING_API_KEY` is set.
    - Key files must be one token of `[A-Za-z0-9._~+/=-]{16,4096}` and must not look like a Google credential (`GOCSPX-`, `ya29.`, `1//`, `-----BEGIN`).
    - `netcheck.check` runs when the address is set and on every request. It allows only a plain host name or a bracketed IPv6 literal, and every resolved address must be public: `is_global` only, so shared address space (100.64.0.0/10: CGNAT, Tailscale, Alibaba metadata) is local. Loopback and private addresses need `GDRAG_ALLOW_LOCAL_EMBEDDINGS=1`, and plain http is allowed only to such a literal address.
    - Requests connect to the checked IP and never follow redirects.
    - A stored key is bound to `embedding_key_origin` (`netcheck.origin()`: scheme://host:port), set with the key and cleared by `remove_embedding`. If the effective address has another origin the key is not used: no client, FTS-only, and `status().embeddings.warning` / `Settings.public()["embedding_warning"]` say so. `GDRAG_EMBEDDING_API_KEY` is exempt. A legacy key with no origin binds once, at first load, to the address in effect then (environment included); `set_embedding` without a new key is refused while the stored key is unbound.
  - `add_source` stores only sources Google (or the local root) confirmed; the CLI `source add` calls `Admin.add_source(queue=False)`, so it too stores nothing unconfirmed, and the server reads it at the next scheduled sync or `gdrive-rag sync`. Links must be on `drive.google.com` or `docs.google.com` exactly. The stored link is rebuilt from the ID.
  - `remove_google_auth` does not revoke the grant at Google; its result says how to. Token refresh and removal share `config.token_lock`. A refresh writes `token.json` only if the file still exists.
  - The OAuth flow (PKCE, state) is held in memory, expires after 10 minutes and is single use. No bare code is accepted over MCP.
  - Changing Google access does not start a sync, because an account without access to a source root would empty it. `add_source` queues a sync.
  - The CLI admin commands apply the same `Admin` methods and precedence: `source add/remove/rules`, `auth google/remove`, `embedding set/remove`, `config import-env`.
  - Do not add more admin tools without the owner's approval.
- The server is stateless JSON-response Streamable HTTP with DNS-rebinding protection allowing only `127.0.0.1`, `localhost` and `[::1]` hosts (extend with `GDRAG_ALLOWED_HOSTS`). In Docker it listens on `0.0.0.0`; compose publishes only `127.0.0.1:8765`.

## Config and secrets

- Settings come from `<data_dir>/config.json` (mode 0600), overridden by `GDRAG_*` variables (`config.ENV_FIELDS`).
  - Admin tools and the CLI admin commands refuse a change that a variable sets to another value, naming the variable (`config.environment_conflicts`), so nothing stored is undone at restart.
  - Fields equal to the environment value are not copied to `config.json`.
  - Every read-merge-write of `config.json` runs under `config.config_lock` (flock on `<data_dir>/.config.lock`); `save_config` is the only writer.
  - `GDRAG_LOCAL_ROOT` (`Settings.local_root`, in `DERIVED_FIELDS`) is environment-only; `config.json` is ignored for it. Docker sets `/local`; compose mounts `${GDRAG_LOCAL_HOST_DIR:-./local}:/local:ro`. Never put it in `.env`.
  - `GDRAG_GOOGLE_AUTH` / `GDRAG_GOOGLE_CREDENTIALS` lock Google access the same way.
  - A source in `GDRAG_DRIVE_LINKS` cannot be removed.
  - `setup --yes` does not copy `.env` into config; `config import-env` does.
  - `sync_status.settings_from` shows `environment (GDRAG_…)`, `stored` or `default` per field, never the value.
- Data dir: `--data-dir`, `GDRAG_DATA_DIR`, else `~/.gdrive-rag`; `/data` in Docker.
- Google files live in `<data_dir>/google/` with mode 0600, written by `config.write_private`. OAuth uses a paste-back flow (`auth.oauth_sign_in`).
- Never print, log or commit API keys, tokens, or credential file contents; `Settings.public()` is the only settings view for output. Tests use fakes only, never real Google or OpenRouter.
